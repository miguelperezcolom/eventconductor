## Entry points

### `ProcessUpstreamEventUseCase`

The main entry point for integration events. Handles process creation, task status updates, message delivery, and timeout/timer checks.

```java
@Autowired
ProcessUpstreamEventUseCase processUpstreamEventUseCase;

// Start a process
processUpstreamEventUseCase.handle(new ProcessUpstreamEventCommand(
    new ProcessCreationRequested(
        "workflow-id",
        "business-key",
        List.of(new Variable("key", "value"))
    )
));
```

### `CancelProcessUseCase` and `RetryProcessUseCase`

Cancellation and retry are dedicated use cases (they are not upstream events):

```java
@Autowired
CancelProcessUseCase cancelProcessUseCase;
cancelProcessUseCase.handle(new CancelProcessCommand(processId));

@Autowired
RetryProcessUseCase retryProcessUseCase;
retryProcessUseCase.handle(new RetryProcessCommand(processId));
```

### `PauseProcessUseCase` and `ResumeProcessUseCase`

Pause a `PENDING`/`RUNNING` process (→ `PAUSED`) and resume it (→ `RUNNING`). Pause holds
the frontier, not in-flight work: worker reports and messages are still accepted, but
successors do not start and timer/timeout clocks freeze (shifted forward by the pause
duration on resume). See [Statuses — Pause semantics](/reference/statuses/#pause-semantics).

```java
@Autowired
PauseProcessUseCase pauseProcessUseCase;
pauseProcessUseCase.handle(new PauseProcessCommand(processId));

@Autowired
ResumeProcessUseCase resumeProcessUseCase;
resumeProcessUseCase.handle(new ResumeProcessCommand(processId));
```

### `PauseWorkflowUseCase` and `ResumeWorkflowUseCase`

Pause/resume a whole workflow definition by id (a plain `String`, no command record):
pausing sets the definition's runtime `paused` flag and pauses all its `PENDING`/`RUNNING`
processes; while paused, new instances (cron included) are created born-`PAUSED`. Resuming
clears the flag and resumes all the definition's `PAUSED` processes.

```java
@Autowired
PauseWorkflowUseCase pauseWorkflowUseCase;
pauseWorkflowUseCase.handle(workflowDefinitionId);

@Autowired
ResumeWorkflowUseCase resumeWorkflowUseCase;
resumeWorkflowUseCase.handle(workflowDefinitionId);
```

### `UpdateStepExecutionUseCase`

Reports task progress from workers. Available as a Spring bean — inject it anywhere.

```java
@Autowired
UpdateStepExecutionUseCase updateStepExecution;

updateStepExecution.handle(new UpdateStepExecutionCommand(
    taskExecutionId,
    List.of(new Variable("result", "ok")),
    "Optional log message",
    StepExecutionStatus.COMPLETED
));
```

Valid `StepExecutionStatus` values for reporting: `RUNNING`, `COMPLETED`, `ERROR`.

Note: the command's first record component is named `stepId` in the source, but the
value to pass is the **task execution id** received in `TaskExecutionRequested` (it is
the step *execution* id, not the step id from the definition). The `Variable` here is
`io.mateu.workflow.domain.aggregates.Variable`.

## Repositories

### `ProcessRepository`

Extends `CrudStore<Process>` and adds `findByBusinessKey` and `countByStatus`.

```java
@Autowired
ProcessRepository processRepository;

// Find by ID
Optional<Process> process = processRepository.findById(processId);

// Find by business key
Optional<Process> process = processRepository.findByBusinessKey("order-123");

// List all
List<Process> processes = processRepository.findAll();

// Count by status (there is no findByStatus — filter findAll() for listings)
long running = processRepository.countByStatus(ProcessStatus.RUNNING);
```

### `StepExecutionRepository`

Extends `CrudStore<StepExecution>` and adds a few query methods:

```java
@Autowired
StepExecutionRepository stepExecutionRepository;

// Find by process (takes the aggregate, not an id)
List<StepExecution> steps = stepExecutionRepository.findByProcess(process);

// Steps awaiting or in execution, system-wide
List<StepExecution> active = stepExecutionRepository.findPendingOrRunning();

// …or of a single process. Prefer this whenever you know the process: the
// system-wide query grows with every step waiting anywhere in the engine.
List<StepExecution> live = stepExecutionRepository.findPendingOrRunningByProcessId(processId);

// Live steps whose deadline (a TIMER's due moment, or a step timeout) has passed.
// This is what the scheduler uses; it is an indexed lookup on the deadline, so it
// costs what is due rather than what is waiting.
List<StepExecution> due = stepExecutionRepository.findDue(LocalDateTime.now());
```

### `WorkflowDefinitionRepository`

A plain `CrudStore<WorkflowDefinition>`:

```java
@Autowired
WorkflowDefinitionRepository workflowDefinitionRepository;

// Find by ID
Optional<WorkflowDefinition> def = workflowDefinitionRepository.findById("my-workflow");

// List all active (no findByStatus — filter findAll())
List<WorkflowDefinition> active = workflowDefinitionRepository.findAll().stream()
    .filter(d -> d.status() == WorkflowDefinitionStatus.ACTIVE)
    .toList();

// Save/update
workflowDefinitionRepository.save(definition);
```

## Embedded worker interface

```java
@FunctionalInterface
public interface EmbeddedTaskExecutor {
    void execute(TaskExecutionRequested request);
}
```

Register as a Spring bean with the bean name matching the step's `topic` field:

```java
@Bean("my-topic-name")
public EmbeddedTaskExecutor myWorker(UpdateStepExecutionUseCase updateStepExecution) {
    return request -> {
        // ... do work ...
        updateStepExecution.handle(new UpdateStepExecutionCommand(
            request.taskExecutionId(),
            List.of(),
            "",
            StepExecutionStatus.COMPLETED
        ));
    };
}
```

## Domain model

### `Process`

| Field | Type | Description |
|---|---|---|
| `id` | String | Unique process ID |
| `name` | String | Name of the workflow definition at creation time |
| `workflowDefinitionId` | String | ID of the workflow definition |
| `workflowDefinitionVersion` | int | Version of the definition the process runs on |
| `businessKey` | String | Optional human-readable identifier |
| `status` | ProcessStatus | Current status |
| `completionPercentage` | int | Progress indicator (0–100) |
| `variables` | List\<Variable\> | Process variables |
| `created` | LocalDateTime | Creation timestamp |
| `started` | LocalDateTime | When execution started |
| `finished` | LocalDateTime | When the process reached a terminal status |
| `pausedAt` | LocalDateTime | Set while the process is `PAUSED`; used to shift step clocks on resume. `null` otherwise |

### `StepExecution`

| Field | Type | Description |
|---|---|---|
| `id` | String | Unique step execution ID — this is the `taskExecutionId` that workers receive and must echo back in `UpdateStepExecutionCommand` |
| `processId` | String | Parent process ID |
| `workflowDefinitionId` | String | Workflow definition ID |
| `stepId` | String | Step ID from the workflow definition |
| `status` | StepExecutionStatus | Current status |
| `workerId` | String | Worker that took the task |
| `order` | long | Execution order within the process |
| `startedAt` | LocalDateTime | When the step started |
| `finishedAt` | LocalDateTime | Set when the step reaches a terminal status |
| `attemptCount` | int | Attempts already made (0 = first attempt, 1 = first retry, …) |

### `Variable`

```java
record Variable(String name, String value) {}
```

There are two `Variable` records with this shape: `io.mateu.workflow.dtos.Variable`
(used by the integration events `TaskExecutionRequested`, `TaskStatusChanged`,
`ProcessCreationRequested`) and `io.mateu.workflow.domain.aggregates.Variable`
(used by `UpdateStepExecutionCommand` and the aggregates). Import the one that
matches the API you are calling — they are not interchangeable.

### `WorkflowDefinition`

| Field | Type | Description |
|---|---|---|
| `id` | String | Unique workflow ID |
| `name` | String | Human-readable name |
| `description` | String | Optional description |
| `version` | int | Version number |
| `status` | WorkflowDefinitionStatus | DRAFT, ACTIVE, DISABLED, ARCHIVED |
| `paused` | boolean | Runtime pause flag, orthogonal to `status`: while true, all the definition's processes are held and new instances are created born-`PAUSED` |
| `draftOfId` | String | Set on working copies: the ID of the definition this drafts |
| `cronExpression` | String | Optional Spring cron expression for scheduled starts |
| `limitConcurrentExecutions` | boolean | Whether to cap concurrent processes |
| `maxConcurrentExecutions` | int | The cap, when limited |
| `enqueueOnLimit` | boolean | Queue starts that exceed the cap instead of rejecting them |
| `defaultMaxStepExecutions` | int | Default per-step execution cap (0 = unbounded) |
| `steps` | List\<Step\> | Step definitions |
